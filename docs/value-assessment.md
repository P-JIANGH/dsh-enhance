# dsh-enhance 的存在价值评估

> 日期：2026-09-30。依据：live 运行时的服务/工具清单（`cordis_inspect`）、上游包源码与 README、本仓库代码/测试/台账。
> 一句话结论：**作为"能力包"，独特面比 README 宣称的小得多；作为"纪律/政策包 + 验收脚手架"，价值是真的——只能靠做减法维持，靠加功能只会越来越薄。**

## 1. 上游已经提供的（不要重复）

技能与 `/` 触发、人类指令注册表、行式 agent 预设、目标续作（`goals` + `dsh-goal-round-driver`）、团队（Agent Teams）、子代理 spawn/fork、日程、工作流、插件管理、终端、附件、权限预设、设置卡片、`AGENTS.md` 指令链、工具结果剪枝、先读后写策略。
→ 任何"我们也来一个 X"之前，先在 live 运行时核对上游是否已提供（`AGENTS.md` Non-goals）。

## 2. 本插件真正新增的（按可替代性）

- **A. 机制级，上游没有**：写令牌（一个工作区一个写者，在工具管线里强制，持有进程已死即可接管）；交付门卫（把"我完成了"当声明判定，绑定可执行 `verify`，产出结构化报告并推进 work 状态/释放令牌）。这是最硬的差异面。
- **B. 内容级（选品，可替代性高）**：3 个打包技能、`work-rules` 段、enhance-mode 深度工作段、6 个角色的人设/预设——都是观点与文案，任何用户都能用原生机制自己写。
- **C. 便利/诊断级**：`dsh_enhance_doctor`、`/doctor`、`/boulder`、librarian 的 `web_search` 授权。
- **D. 工程资产**：隔离实驱 QA（`.dsh-enhance/desktop-test-home` + 驱动 + 证据纪律）、预设字节 pin、修复台账。历史上一批真 bug 都是它抓出来的。

## 4. 继续投入的方向

1. **做减法优先**：新增能力前先看第 3 节；`AGENTS.md` 的 Non-goals 是这份评估的执行形态。
2. **加厚护城河**：交付门卫的 verify 模板库、受保护文件 manifest、报告落盘；写令牌的进程锁与孤儿回收。
3. **收紧对外承诺**：只承诺"纪律默认值 + 诊断 + 可验证验收"。
4. **把 QA 骨架与台账当一等资产**：它证明过自己能抓真 bug。
5. 若要产品化，护城河只能是"**强制 + 可验证**"——提示词与技能谁都能抄，机制上游随时会补。

## 5. 还需要这个项目吗

- **需要**，如果你要的是**纪律的默认值**（默认先读文件核事实、小步可审查、留下可验证证据、不许假称完成、一个工作区一个写者）。上游给的是机制，政策得自己定。
- **不需要**，如果你要的是**能力**：技能、预设、指令、目标、团队、日程、工作流、审查，上游都有或在补。
- **最诚实的定位**：一份个人化的**政策包 + 真跑的验收脚手架**（外加 oh-my-zsh 式选品）。价值随"你多在意不许假称完成"上升，随"上游又补了哪一块"下降——所以长期动作是**删减**，不是扩张。
